# 供应商订单交付与发票上传

## 供应商入口

在 `/supplier` 使用已有供应商账号登录，顶部三个模块为：询价报价、订单交付、发票上传。新功能沿用供应商独立会话，不需要创建新的登录账号。

### 订单交付

1. 采购方在采购订单中将订单设为“已发送”，供应商才能看到；草稿、待审批及未发送订单不展示。
2. 供应商“确认接单”后进入待送货状态。
3. “登记发货”选择订单物料、本次数量、承运商、运单号、发货日与预计到货日。允许分批发货；含待确认发货在内的累计数量不得超过订单数量，已完成退货可释放补货数量。
4. 发货生成采购端草稿收货单，不计为实际收货。采购方在“收货、质检与退货 → 供应商交付记录”核对物流并确认实际收货。数量不符时先编辑对应收货单数量。
5. 确认收货时记录实际收货日期，后续沿用质检、退货及订单完成状态逻辑。供应商可在交付记录看到状态更新。
6. 未实际收货前可撤回并重新提交；采购方已收货的记录不能撤回。采购方不能直接删除供应商预通知关联的草稿收货单，需由供应商先撤回。

### 发票上传

1. 采购方先创建并确认订单对账单，供应商上传时只能选择自己订单的已确认对账单。
2. 填写发票号码、含税金额、税额和开票日期，上传一个 PDF、PNG 或 JPEG 文件（最大 10MB）。累计非驳回发票金额不能超过对账金额，税额不能大于含税金额，发票号码不能重复。
3. 上传后自动进入采购端“对账、发票与付款 → 供应商发票”，状态为待验真，可下载附件、验真或驳回。
4. 验真属于采购人员审核记录，并非自动连接税务机关。当前不包含 OCR、电子签章校验或税务平台验真。
5. 供应商可下载自己上传的附件、查看审核状态；待验真或驳回且未进入付款流程的发票可撤回重传。已验真发票不能撤回。
6. 为保持附件与数据一致，采购方不能直接修改或删除供应商上传的发票；应驳回后由供应商撤回重传。

## 分页、权限与存储

- 新列表支持分页及字段类型组合查询。发货与发票记录仅显示所属供应商数据；跨供应商订单、发货及文件访问均由后端限制。
- 采购端交付与发票附件读取要求采购业务编辑角色。供应商账号维护仍仅限系统管理员。
- 新增 `supplier_deliveries`、`supplier_invoice_files` 两张表；不修改原订单与发票表结构。
- 发票保存在 `apps/api/private_supplier_invoices/`（以 API 运行目录为准），不挂载静态文件路由。生产备份需同时备份数据库及此目录。下载经登录/权限检查，并强制附件下载。文件扩展名和文件头均检查；本版本未接入恶意文件扫描服务。
- 原供应商网关 `/api/v1/supplier/` 白名单已覆盖新接口，不应将内部采购 API 全部开放到公网。

## 主要接口

- `GET /api/v1/supplier/orders`；`POST /api/v1/supplier/orders/{id}/confirm`
- `GET/POST /api/v1/supplier/deliveries`；`DELETE /api/v1/supplier/deliveries/{id}`
- `GET /api/v1/supplier/reconciliations`
- `GET/POST /api/v1/supplier/invoices`；`DELETE /api/v1/supplier/invoices/{id}`
- `GET /api/v1/supplier/invoices/{id}/file`
- 内部：`GET /api/v1/supplier-deliveries`、`GET /api/v1/invoices/{id}/file`

API 测试：`apps/api/tests/test_supplier_execution.py`。浏览器闭环测试：`apps/web/tests/supplier-execution.e2e.js`（连接隔离 API 18001，不使用业务库）。
